# 知识库设计

## 职责和边界

知识库引擎负责材料切分、索引和检索，不依赖内容生成后端。后端适配器把生成请求转为检索查询，再把结果转换成 `RetrievalResult`：片段列表加上明确的成功、空结果或失败状态。

原始文档由使用者自行提供。运行版本不分发外部语料、实验标注和特定语料的评测结果。独立建库与增删命令保留，实验工具私有归档。

## 切分和来源

当前按 Markdown 小节切分，长小节采用最多 800 字符、重叠 120 字符的窗口，并尽量在句子或段落边界结束。重叠帮助跨窗口保留上下文；限制窗口长度可以控制向量输入和生成上下文的体积。

片段保留文档编号、标题、小节、来源地址和正文位置。文档编号取自文件名，片段编号由文档、小节和窗口序号组成。标题和小节加入向量输入，也用于关键词字段加权，使正文中的局部片段保留主题信息。

这些参数是工程默认值。资料长度、语言和文档结构变化后，需要用自己的实际问题检查检索效果；这里不声称它们对任意语料最优。

## 关键词和向量融合

关键词索引使用 jieba 分词和 BM25，适合具体术语及产品名称。向量检索适合用不同措辞表达的语义需求。两类分数的尺度不同，因此使用 RRF（倒数排名融合），根据各通道中的名次计算融合分数。

`hybrid` 使用等权融合。默认 `router` 判断查询中英文术语的占比，对术语较多的查询增加关键词通道权重；语义查询增加向量通道的相对权重。当前关键词／向量权重分别为 1.5／1.0 或 0.5／1.0，RRF 常量为 60。这是轻量的查询类型判断，避免硬性限定资料主题。

查询由主题、生成要求、阶段和当前章节信息组成。构建查询时应尽量保留具体教学目标，避免重复堆叠无关要求。特定资料上的检索指标不能直接推广到其它资料。

## 结构过滤

索引排除参考文献、目录及明显的文档提取残留。正文中的普通引用链接不会仅因出现链接就全部删除。

原始片段缓存保持完整，建库和在线关键词索引使用同一个过滤规则。向量结果再映射到当前有效片段集合。这样可以保留原文以便重新处理，同时避免被过滤内容通过另一条检索通道重新返回。`KB_FILTER_JUNK` 控制是否启用过滤。

## 向量存储与文档更新

向量模型不同，即使维度相同也使用不同集合。切换模型时需要为对应集合建库。

Qdrant point ID 使用片段编号生成稳定 UUID。撤回文档后，不通过当前记录数量计算下一编号，因此编号空洞不会覆盖其它文档。替换文档时按文档编号移除旧向量，再写入当前片段；较短的新版本不会留下旧尾部片段。

向量生成成功后再修改片段缓存。更新完成后检查缓存、关键词索引与向量数量是否一致。退出命令时显式关闭本地存储，保存集合变更。

本地 Qdrant 目录适用于单进程使用。维护索引时需要停止读取同一目录的后端。当前实现没有提供在线多进程写入或跨存储事务；原始文档和明确的重建命令是恢复来源。

## 任务附件

平台知识库与任务附件独立检索。附件只在当前请求内切分和建立关键词索引，向量在内存中检索，不写入平台集合。重复正文的向量在进程内缓存，以减少重复调用。

三种模式分别为平台库、仅附件、两者融合。融合时对附件使用略高的排名权重，因为附件通常与当前任务目标直接相关。仅附件模式不初始化平台索引，因此没有平台语料时仍可使用。

这保证当前检索流程中的材料范围；当前版本未实现账号授权或持久的多用户知识库权限控制。`knowledge_base_ids` 仍是保留字段。

## 失败行为和学习流程

初始化、模型配置和检索错误都转为明确的失败状态；空结果单独标记，避免被误认为已经使用了知识库。检索适配器不替换为虚构的引用。

互动讲义生成复习任务时，保留原请求的材料、检索模式和明确指定的生成选项，在此基础上追加复习要求并调整难度。学习服务只负责记录与摘要，不承担知识库索引职责。
