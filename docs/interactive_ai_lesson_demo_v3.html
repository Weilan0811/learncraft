三个关键词：Token、上下文、概率预测

大语言模型处理问题时，会把文本转换成可计算的表示，在上下文窗口中整合当前可见的信息，并一步步预测下一个合适的内容。为了便于理解，可以把它想象成“读题、找线索、组织答案”的连续过程。

🔤

Token：文本被拆成小片段

token 可以是字、词或词的一部分。模型处理的是 token 的向量表示，而不是直接处理人眼看到的完整句子。

输入处理可计算化
🧩

上下文：当前能参考的信息

上下文包括用户问题、历史对话、检索到的资料、系统提示和输出格式约束。上下文越清楚，回答越容易稳定。

资料约束
🎯

概率预测：逐步生成答案

模型会根据已有 token 预测后续内容。一个完整回答，通常是许多次连续预测和约束选择的结果。

生成连贯性
讲给初学者的一句话：生成式 AI 不是“一眼看懂后直接吐答案”，而是把问题变成可计算的上下文，再一步步生成最合适的回答。

同一个问题，为什么回答质量会差很多？

学生的问题经常很短：“RAG 是什么？” 模型如果只靠通用知识回答，可能正确但泛泛；如果系统补充课程目标、教材片段和例子要求，回答会更贴合学习场景。

普通回答

RAG 是检索增强生成，指模型在回答前先检索相关文档，然后基于文档生成回答。

定义正确解释较短缺少教学引导

带教学上下文的回答

可以把 RAG 想象成“开卷考试”：AI 先从资料库里找和问题有关的内容，再根据资料组织答案。这样回答更贴近指定教材，也更容易说明依据。

简答题：请解释“为什么互动式 HTML 课件适合做生成式学习材料？”

参考评分点：
  • HTML 能承载动画、折叠、Tabs、拖拽、测验、对话等丰富交互。
  • 纵向教材式页面适合逐步讲解，也比固定页 PPT 更适合承载长内容。
  • 互动数据可以用于学习进度记录、个性化反馈和后续补充生成。
  • 工程上可以用 LessonBlock schema 统一生成与渲染，提升稳定性。
总结回顾

这版 demo 重点展示三件事

1. 动画流程可模板化

animated_flow 只需要步骤数据，动画样式、对齐和状态切换由前端统一控制。

2. 对话教学可模板化

多轮问答和情景教学由 rounds / scenes / choices 驱动，演示时能形成真实对话感。

3. 互动题型可模板化

单选、多选、拖拽匹配、排序、翻卡、简答评分点都能作为 LessonBlock 渲染。

4. AI 不直接写页面

AI 生成 LessonSpec / LessonBlock JSON，Renderer 负责样式、动画和交互逻辑。

工程化提示：后续 interactive_html 可以定义为 InteractiveLessonSpec，其中 blocks[] 支持 hero、explain_card、animated_flow、case_compare、socratic_chat、scenario、quiz、drag_match、sequence、flashcard、reflection 等类型。

  "layout": "vertical_lesson_with_tutor",
  "blocks": [
